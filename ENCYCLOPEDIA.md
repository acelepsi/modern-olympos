## Collection and security changes (deployment required)

The only new Firestore collection is `encyclopedia/{characterId}`. IDs generated by the SDK are independent of accounts. A document contains exactly the following string fields, with no timestamps, owner identifiers or student data:

| Field | Maximum length | Notes |
| --- | --- | --- |
| name | 100 | Nonblank |
| tradition | 80 | Nonblank, teacher-defined; no fixed taxonomy |
| introduction | 500 | Nonblank |
| biography, actions, perspectives | 8000 each | May be empty in a draft |
| sources | 4000 | Teacher-supplied text/citations; may be empty in a draft |
| portraitUrl | 2000 | Empty or HTTPS without credentials/whitespace |
| relatedTrialId | 80 | Empty or existing lowercase trial ID |
| status | enum | `draft` or `published` |

Published entries require nonblank biography, actions, perspectives and sources. All fields are required in stored documents, with optional values represented by empty strings. The teacher editor constructs the complete whitelist; unknown fields are rejected by rules. Publication is an explicit status choice plus Save, not automatic content generation. All content renders as plain text; sources are not parsed as HTML or converted into arbitrary links. No factual biographies, citations or historical entries are prepopulated.

New rules apply only inside the new collection. Anonymous visitors/students may get/list published documents; draft gets and unfiltered public lists fail. Public code uses `where('status','==','published')` with client-side sorting, so no composite index is needed. The existing pinned administrator UID function controls all creates/updates/deletes and access to drafts. Another teacher profile alone grants no permissions. Related IDs must match existing trial IDs; entries never create/change a trial. Existing rules for students, trials, moderation, votes, closure, verdicts and reasoning are unchanged.

The new teacher controller receives the existing `auth`/`db` objects, avoiding a second initializer/emulator connection. It verifies the existing active-teacher profile and an administrator-only unfiltered server list before enabling tools. User/context revisions suppress stale loads and feedback, pending operations block duplicate writes, failed writes stay unconfirmed, and a new-entry ID is retained for safe retry after a lost acknowledgement. Permanent deletion requires confirmation; setting Draft is the reversible unpublish alternative. Editing from two devices still follows normal last-write-wins Firestore behavior.

## Public reading and navigation

`who-is-who.html` lists published cards, filters by name/tradition in memory, and supports `?character=<id>` for a complete entry. A draft or missing ID has an unavailable state; there is no private fallback read. Per refresh, related trials use a shared settings read and one public trial read per unique related ID. Completed links use the existing `archive.html?trial=<id>` route. Only a verified active open case links to the court; other/missing/unverified cases are labeled without a misleading courtroom link. No per-keystroke reads.

An unpublish/delete prevents subsequent authorized public reads. Copies of previously published text already loaded in a browser remain visible until refresh and cannot be recalled. Content must be reviewed before publication; never include student identities or private classroom information. This feature does not attempt automatic PII detection.

The complete prior classroom guide and privacy guidance are preserved in `how-it-works.html`, linked from shared navigation, the encyclopedia, landing page and teacher dashboard. No existing participation instructions are discarded.

## Visual changes and licensing

Cards/detail/editor use the established charcoal/gold typography and contained portrait fallback. The court mount is slightly wider, keeps a contained image for landscape/portrait artwork, and retains the gold frame/Ω. Aspect-ratio letterboxing cannot be eliminated without cropping or stretching. The background now reuses/refines the project's original CC0 museum-entrance architecture with visible fluted columns, relief and depth, positioned to retain capitals in a shallow header. `courtroom-architecture.svg` remains original CC0 1.0 artwork; no third-party images or libraries are introduced. Archive portrait treatment is unchanged.

1. Review/test the PR and follow the existing owner-controlled merge/release process.
2. Run `npm.cmd ci`, `npm.cmd run test:all`, `node tests/portrait-layout.browser.cjs`, and `node tests/platform-polish.browser.cjs` with the existing demo emulator setup. CI runs these checks without production data.
3. Prepare the reviewed site/rules together with `npm.cmd run prepare:launch -- --admin-uid YOUR_EXISTING_TEACHER_UID`. This writes local launch artifacts only; it does not deploy. Keep the same existing designated UID. Do not deploy the unchecked placeholder template.
4. Through the existing authorized release procedure, publish the prepared Firestore rules and website assets together. Without the new rules the new collection stays denied; existing collections continue using their existing protections.
5. In the teacher dashboard, author a private entry, verify it is unreadable while signed out, then publish and check the public card/detail/source/related link. No migration, Firebase Console setting, backend, Storage bucket or automatic production seed is needed.

Manual checks: synthetic teacher create/edit/publish/unpublish/delete and cancellation, account switch during pending operations, empty/error states, real-phone keyboard/screen-reader navigation and external portrait URLs. Test content should be synthetic and entered only into local emulators. Browser fixtures test actual DOM/controller logic with mocked data, not a deployed authenticated browser session. Production data, deploys and automatic merge are outside this task.
